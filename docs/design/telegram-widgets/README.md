# Карточки Мунина в Telegram

Карточки используют один проверяемый HTML-шаблон и приватное состояние сообщения. Напоминание позволяет взять дело в работу, завершить его через обычные кнопки или перенести напоминание на час. Проверка результата спрашивает, получилось ли завершить дело. Сообщение после перерыва открывает Мунин и позволяет отключить такие приглашения. Разбор текста или голосового показывает предложенные изменения, срок, день работы и напоминание до применения.

У предложения с несколькими действиями есть листание, выбор и счётчик применяемых изменений. Взаимоисключающие варианты выбираются по одному. Уточнения, неразобранные части запроса, слишком большой результат и изменение более двух полей за раз остаются в полном текстовом представлении. Время на примере с парой — тестовые данные, а не результат нового запуска распознавания.

## Включение

`TELEGRAM_WIDGETS_ENABLED=true` включает отправку и обработку карточек в core-service и notification-worker. По умолчанию флаг выключен. Отдельная настройка пользователя «Карточки в Telegram» меняет вид будущих сообщений; `/plain` включает обычные сообщения, `/cards` возвращает карточки. Она не включает напоминания или приглашения, которые пользователь отключил.

Под карточкой остаются «Подробнее» и ссылка на Мунин. «Подробнее» раскрывает обычные кнопки в том же сообщении. Это путь для клиентов без поддержки виджетов. При явном отказе Bot API поддерживать `sendWidget` отправляется текст с кнопками. При сетевом таймауте запасная отправка не выполняется сразу: неизвестно, принял ли Telegram первый запрос.

## Действия и доставка

Bot API передаёт запрос в обычный защищённый webhook. Для `widget_query` используется отдельная очередь исполнения, чтобы нажатие не ждало разбора голосового. Перед изменением проверяются Telegram-идентичность, владелец, чат, сообщение, версия, срок жизни карточки и актуальность задачи. Устаревшая версия возвращает сохранённое состояние. Перед выполнением после блокировок повторно проверяется срок запроса; просроченное нажатие не начинает изменение.

Ключ имеет вид `w:<context UUID>:<revision>:<action>`. Он ссылается на сохранённый контекст, а не содержит доверенные ID пользователя, задачи или даты. Кнопки работают через TaskService, AssistantService и EngagementService, без нового обращения к модели. Подтверждение предложения проверяет ожидаемые действия под блокировкой самого предложения. Частичный результат показывает фактическое число сохранённых изменений.

Новое состояние и задание `WIDGET_SYNC` фиксируются одной транзакцией. Обновления сообщения используют существующую очередь доставки с арендой, повторными попытками и разбросом задержек. Несколько изменений объединяются, но подтверждение старой доставки не погашает новую версию. После объединения аккаунтов старый захват не отправляет актуальные данные в прежний чат. Завершение задачи не удаляет задание обновить её карточку.

Перенос напоминания не меняет срок задачи. Для настойчивого напоминания учитывается уже продолженная цепочка: переносится следующий ожидающий повтор, а не создаётся параллельный.

## Просмотр и проверки

```sh
python3 -m http.server 4182 --bind 127.0.0.1 --directory docs/design/telegram-widgets
```

Открыть http://127.0.0.1:4182/preview.html. Предпросмотр использует заглушку ответа; настоящие изменения проверяются интеграционными тестами.

Проверка на официальной песочнице `TelegramMessenger/widget-sandbox`, commit `eed3271`:

```sh
node --import tsx /path/to/taskflow/docs/design/telegram-widgets/verify.mjs /path/to/widget-sandbox
```

Проверяются светлая и тёмная темы, отсутствие запросов при загрузке, действия, сетевой отказ, повторное получение старого состояния, безопасный вывод названия, листание и пустой выбор. Шаблон в `core-service/shared/telegram-widgets` совпадает с файлом предпросмотра. Ограничения контролируются в коде: HTML до 32 768 байт и 4096 после zlib-9; ответ с состоянием до 1024 байт; ключ до 64 байт. Внутренней прокрутки, загрузки библиотек и периодического опроса нет. Размеры и кнопки отдельно проверены в Chrome на ширинах 280–440 px.

HTTP-контракт Bot API проверяется на заглушке. Тесты PostgreSQL покрывают владение, привязку сообщения, повторные и одновременные нажатия, перенос срока, цепочку напоминаний, частичный результат, изменение предложения, атомарную запись очереди и смену адресата после захвата доставки. Они не отправляют сообщения в настоящие Telegram-чаты.

Документация: [Telegram Widgets](https://core.telegram.org/bots/widgets), [Bot API](https://core.telegram.org/bots/api#sendwidget).

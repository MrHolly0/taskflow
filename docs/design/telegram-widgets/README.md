# Карточки Мунина в Telegram

Карточки используют один проверяемый HTML-шаблон и приватное состояние сообщения. Напоминание позволяет взять дело в работу, завершить его через обычные кнопки или перенести напоминание на час. Проверка результата спрашивает, получилось ли завершить дело. Сообщение после перерыва открывает Мунин и позволяет отключить такие приглашения. Однозначное создание и одиночное завершение из текста или голосового выполняются сразу. Карточка показывает сохранённый результат, а у созданной задачи — срок, день работы и назначенные будущие напоминания. Исправление открывает задачу в Мунине; отмена работает без нового обращения к модели. Неоднозначный разбор и остальные изменения остаются на подтверждении.

У предложения с несколькими действиями есть листание, выбор и счётчик применяемых изменений. Взаимоисключающие варианты выбираются по одному. Уточнения, неразобранные части запроса, слишком большой результат и изменение более двух полей за раз остаются в полном текстовом представлении. Время на примере с парой — тестовые данные, а не результат нового запуска распознавания.

## Включение

`TELEGRAM_WIDGETS_ENABLED=true` включает отправку и обработку карточек в core-service и notification-worker. По умолчанию флаг выключен. Отдельная настройка пользователя «Карточки в Telegram» меняет вид будущих сообщений; `/plain` включает обычные сообщения, `/cards` возвращает карточки. Она не включает напоминания или приглашения, которые пользователь отключил.

У карточки нет текстовой подписи: название, сроки и действия показывает сам виджет. При обновлении старого сообщения дублирующая подпись очищается. Под карточкой остаются «Показать текст» и ссылка на Мунин. «Показать текст» раскрывает подписанное текстовое представление и обычные кнопки в том же сообщении; «Скрыть текст» снова оставляет виджет. Это путь для клиентов без поддержки виджетов. При явном отказе Bot API поддерживать `sendWidget` отправляется текст с кнопками. При сетевом таймауте запасная отправка не выполняется сразу: неизвестно, принял ли Telegram первый запрос.

## Действия и доставка

Bot API передаёт запрос в обычный защищённый webhook. Для `widget_query` используется отдельная очередь исполнения, чтобы нажатие не ждало разбора голосового. Перед изменением проверяются Telegram-идентичность, владелец, чат, сообщение, версия, срок жизни карточки и актуальность задачи. Устаревшая версия возвращает сохранённое состояние. Перед выполнением после блокировок повторно проверяется срок запроса; просроченное нажатие не начинает изменение.

Ключ имеет вид `w:<context UUID>:<revision>:<action>`. Он ссылается на сохранённый контекст, а не содержит доверенные ID пользователя, задачи или даты. Кнопки работают через TaskService, AssistantService и EngagementService, без нового обращения к модели. Подтверждение предложения проверяет ожидаемые действия под блокировкой самого предложения. Частичный результат показывает фактическое число сохранённых изменений.

Новое состояние и задание `WIDGET_SYNC` фиксируются одной транзакцией. Обновления сообщения используют существующую очередь доставки с арендой, повторными попытками и разбросом задержек. Несколько изменений объединяются, но подтверждение старой доставки не погашает новую версию. После объединения аккаунтов старый захват не отправляет актуальные данные в прежний чат. Завершение задачи не удаляет задание обновить её карточку.

Перенос напоминания не меняет срок задачи. Для настойчивого напоминания учитывается уже продолженная цепочка: переносится следующий ожидающий повтор, а не создаётся параллельный.

Описание передаётся отдельным полем из сохранённой задачи, а для предложения создать дело — из его описания. Внутри виджета оно раскрывается локально по нажатию «Описание», без обращения к модели или серверу. Пустое описание и повтор названия не показываются. Длинный текст сокращается под размер карточки; целое описание доступно в задаче. В текстовом представлении название помечено «Задача», а описание — «Описание». При загрузке деталей берутся актуальные название и описание владельца задачи.

## Автоматические действия и отмена

Автоматически сохраняются только полностью разобранные создания задач либо одно однозначное завершение. Уточнение, неразобранная часть фразы, выбор между альтернативами, отклонённое действие, смешанный набор изменений и завершение повторяющейся задачи требуют подтверждения. В приложении этот сценарий обслуживают `/assistant/turn` и `/assistant/capture`; старые `/messages` и CREATE-only `/quick` сохранены для совместимости.

Отмена доступна 24 часа и связана с владельцем, исходным действием и сохранённым состоянием задачи. Создание отменяется мягким удалением; завершение возвращает прежний статус, время начала работы и ожидающие напоминания. Просроченные напоминания не отправляются заново. Если после действия изменились задача, её напоминания, теги или повторение, отмена предлагает открыть задачу для исправления. Повторная отмена не меняет данные ещё раз. Повторная доставка исходного сообщения возвращает сохранённый результат, включая отменённый, вместо повторного создания.

Карточка с несколькими созданными задачами листается по результатам; отмена относится к открытой странице. Кнопка «Изменить» открывает нужную задачу в Mini App. Обычный текстовый режим сохраняет эти же действия. Короткая похвала после завершения выбирается без обращения к модели.

## Вопросы об итогах и возвращение

Для новых пользователей вопросы об итогах и приглашения вернуться включены. Отсутствующая строка настроек получает новые значения, а сохранённый отказ существующего пользователя не перезаписывается. Обе функции можно отдельно выключить в настройках. Выключенные общие уведомления или канал Telegram также запрещают отправку.

Для начатого дела вопрос планируется после оценки длительности плюс 15 минут, без оценки — через час. При близком сроке ориентиром может стать срок плюс 30 минут, но вопрос не приходит раньше чем через 15 минут после начала. Начатое заранее дело с будущим днём работы тоже учитывается; перенос дня после начала откладывает проверку. Повторное нажатие «В работе» не сбрасывает время начала. Для неначатой задачи вопрос становится доступен через 30 минут после срока. Созданной уже с прошедшим сроком задаче сначала даются 30 минут после создания. Наличие неотправленного напоминания не является условием вопроса об итоге.

Пассивные вопросы и приглашения ограничены пользовательскими тихими часами и одним сообщением за 24 часа. Интервал можно изменить в своём часовом поясе или выключить. Назначенные пользователем моменты и карточки срока приходят вовремя; они не расходуют лимит пассивных сообщений. Рядом с обычным напоминанием вопрос откладывается. Прошедшие сроки и давно начатые дела не отбрасываются из-за возраста или перезапуска сервера. При включении вопросов незакрытый backlog тоже учитывается, с общим ограничением частоты. «Ещё в работе» не запускает бесконечную цепочку вопросов; «Напомнить через час» создаёт явное напоминание; при выходе за срок оно сохраняется как вопрос об итоге со снимком срока. Перенос срока отменяет этот устаревший вопрос. После трёх дней без активности возможно приглашение вернуться, не чаще раза в неделю. Даты, состояние задачи, включённые настройки и адресат повторно проверяются перед отправкой.

## Несколько пропущенных дел

Несколько доступных вопросов объединяются в одну отправку: корневая запись `CHECKIN_BATCH` и до 50 дочерних вопросов со снимками конкретных задач. В Telegram приходит одно сообщение с листанием; ответ относится к открытой задаче. После ответа показывается следующее незакрытое дело. Уже отвеченную страницу можно просмотреть без повторного выполнения действия. Обычные inline-кнопки дают то же поведение без поддержки HTML-карточек.

Планирование и очередь доставки записываются одной транзакцией. Повторный проход не создаёт новые вопросы для того же срока или попытки работы. Если группа истекла, пока сервер не работал, неотправленные дочерние вопросы отменяются и снова доступны для планирования. Для отправленной группы сохраняются прежние ответы. Закрытая, удалённая или перенесённая задача не завершается старой кнопкой; ревизия карточки не даёт повторному нажатию затронуть следующую страницу.

За один суточный интервал отправляется одна группа или одиночный вопрос. Если накопилось больше 50 дел, остальные остаются доступными для следующего интервала. Если включены вопросы об итогах, старые Telegram-напоминания по уже просроченным срокам ожидают объединённого вопроса, даже когда отправщик восстановился раньше планировщика. Они удаляются из старой очереди только после подтверждённой отправки вопроса. Это ожидание не расходует попытки доставки. Свежие явные напоминания и отключённые вопросы сохраняют обычную доставку.

## Ограничение расходов

Текст и голос в боте используют общий контроль частоты, параллельности и суточного бюджета модели. Для голосового проверяются заявленная длительность и допуск до загрузки файла; существующий контроль продолжительности аудио остаётся после загрузки. Отказ по лимиту возвращает одно сообщение без повторного платного разбора через очередь. Отмена, листание и кнопки карточек не вызывают модель. Значения лимитов настраиваются через общий ResourcePolicy.

## Просмотр и проверки

```sh
python3 -m http.server 4182 --bind 127.0.0.1 --directory docs/design/telegram-widgets
```

Открыть http://127.0.0.1:4182/preview.html. Предпросмотр использует заглушку ответа; настоящие изменения проверяются интеграционными тестами.

Проверка на официальной песочнице `TelegramMessenger/widget-sandbox`, commit `eed3271`:

```sh
node --import tsx /path/to/taskflow/docs/design/telegram-widgets/verify.mjs /path/to/widget-sandbox
```

Проверяются светлая и тёмная темы, отсутствие запросов при загрузке, действия, сетевой отказ, повторное получение старого состояния, безопасный вывод названия, листание, пустой выбор и отмена результата без подтверждения. Шаблон в `core-service/shared/telegram-widgets` совпадает с файлом предпросмотра. Ограничения контролируются в коде: HTML до 32 768 байт и 4096 после zlib-9; ответ с состоянием до 1024 байт; ключ до 64 байт. Внутренней прокрутки, загрузки библиотек и периодического опроса нет. Размеры и кнопки отдельно проверены в Chrome на ширинах 280–440 px.

HTTP-контракт Bot API проверяется на заглушке. Тесты PostgreSQL покрывают владение, привязку сообщения, повторные и одновременные нажатия, перенос срока, цепочку напоминаний, частичный результат, изменение предложения, атомарную запись очереди, смену адресата после захвата доставки, отмену создания, защиту от повторного выполнения и правки задачи после действия. Они не отправляют сообщения в настоящие Telegram-чаты.

Документация: [Telegram Widgets](https://core.telegram.org/bots/widgets), [Bot API](https://core.telegram.org/bots/api#sendwidget).

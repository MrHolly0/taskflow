# Вариант доски

`board-concept.html` — самостоятельный интерактивный пример для обсуждения. Он не обращается к API и не меняет задачи приложения. Внешние библиотеки не добавлены. Тема меняется только в полосе управления примером; в продукте остаётся в настройках.

## Что есть сейчас

Изучены `BoardPage.tsx`, типы `Task`/`Status`, `TaskDetailModal`, `AppLayout`, утверждённые стили `munin.css` и предыдущий HTML-концепт.

Доска показывает три статуса: «К выполнению», «В работе», «Готово». Отменённые задачи скрыты. Положение карточки меняет статус; сортировка внутри колонки не реализована. Клик открывает общую форму задачи. Карточка показывает приоритет, срок, группу и ближайшее напоминание. Форма дополнительно позволяет изменить описание, оценку времени, повтор и настойчивость напоминаний.

На компьютере все три колонки видны рядом. Захват мышью начинается после движения на 8 px. Сенсорный захват активируется после 200 ms, с допуском 5 px. Коллизия сначала проверяет положение указателя, затем пересечение прямоугольников. Есть автопрокрутка. Вся карточка захватывается и имеет `touch-none`.

До 767 px включительно существуют два режима. По умолчанию статусы идут друг под другом. Во втором режиме ширина каждой колонки 87%, доступны свайп, стрелки и индикаторы. Выбор сохраняется в `taskflow.boardView`. При переносе привязка прокрутки к колонкам отключается. Кнопки «+» в колонках сейчас открывают свободный ввод. Все карточки выводятся сразу, поэтому 50–120 задач отодвигают следующие статусы далеко вниз.

## Предложение

Сохранить три статуса и оба мобильных режима. Главный визуальный акцент — сами задачи, не дополнительные графики или фильтры. Общий хедер, точный знак Мунина и глобальная кнопка рассказа продолжают утверждённый интерфейс. Внутри колонок кнопки добавляют задачу вручную, сразу в нужный статус.

| Сценарий | Вариант |
| --- | --- |
| Большой список на компьютере | Колонки ограничены высотой доступного экрана, заголовки остаются видны. Порция 8 карточек, полный счётчик и «Ещё». Прокрутка происходит внутри списка. |
| Большой список на телефоне, вертикально | Порция 4 карточки в каждом статусе, полный счётчик и «Ещё». Нет внутренней вертикальной прокрутки. Следующие статусы не уходят на десятки экранов. |
| Телефон, по статусам | Колонки 87%, свайп и стрелки сохранены. Подписанные кнопки статусов заменяют неинформативные точки. Внутренний список прокручивается. |
| Выполнение | Кольцо отмечает завершение. В «Готово» это же кольцо возвращает в список. «Начать», «Завершить», «Вернуть» доступны на карточке, дополнительные действия через ПКМ / ⋯ / удержание. |
| Длинное название | Полностью переносится по строкам. Высота карточек определяется содержимым, задача не обрезается до двух строк. |
| Перенос | Захват за отдельную ручку. Исходная карточка остаётся на месте, цель получает пунктир. Статус меняется только после отпускания непосредственно в колонке. Отпускание вне неё, в зоне отмены или Esc сохраняет исходный статус. |
| Клавиатура | Ручка: пробел или Enter для захвата, стрелки для выбора статуса, Enter для переноса, Esc для отмены. Есть объявления состояния. |
| Создание и сохранение | Новая или изменённая задача раскрывается в своей колонке и кратко подсвечивается без изменения отступов. |
| Поиск | Ищет по названию и группе, сохраняет три колонки и их счётчики для результата. Есть явный сброс. |

## Что проверять в примере

Полоса сверху включает нагрузку «50+ задач», пустую колонку, темы и сброс. Ручное создание работает прямо в колонке. Название открывает редактирование: срок, группа, приоритет, оценка, описание и демонстрационное напоминание. Выполнение, начало, возврат и отмена меняют только локальные данные. Меню закрывается вне него, формы закрываются по внешней зоне и Esc. Пользовательский выбор мобильного режима сохраняется отдельно от приложения.

Свободный рассказ явно помечен локальным примером: одна текстовая задача без разбора. Микрофон и загрузка аудиофайла здесь не имитируются. Реальный разбор, повторы, списки напоминаний, серверные ошибки, согласование конкурентных изменений и интеграции остаются задачами переноса в React после обсуждения. Действующая `BoardPage.tsx` не изменена.

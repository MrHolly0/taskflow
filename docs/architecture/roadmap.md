# Следующие задачи

Зафиксировано 08.11.2026. Порядок согласован после проверки замены планировщика.

## Текущее состояние

JSON-планировщик объединён с локальной main; результаты и ограничения приведены в [отчёте](json-planning-replacement.md). Статья по методам дополнена повторным сравнением и проверкой списков по 100/200 задач. Статья по интерфейсу остаётся без новых экспериментальных выводов.

## Следующий приоритет: ресурсы и защита от злоупотреблений

В отдельной ветке `model-resource-guards` реализованы [исправления](model-resource-guards.md) по замечаниям из [аудита](model-resource-protection-review.md): сетевую границу, общий дедлайн и параллельность worker, повторные одновременные запросы, бюджет внешних API и распределение слотов между пользователями. В аудите указаны подтверждённые места в коде и условия приёмки. Основная ветка и рабочий стенд пока не обновлены. Перед выкладкой нужны общий внутренний секрет core/worker и отдельная проверка доверенных proxy Tuna.

## Позже: краткое обучение при первом входе

От актуальной main создать отдельную ветку `user-onboarding`. Сейчас ветку не создавать и обучение не реализовывать: сначала работы по защите ресурсов.

Пользователь при первом входе получает короткое объяснение основных действий и советы по месту: рассказать Мунину текстом или голосом, проверить предложенные изменения, воспользоваться ручным созданием и управлять задачей. Не превращать знакомство в обязательную длинную экскурсию.

При проработке предусмотреть пропуск, запоминание завершения и повторное открытие подсказок. Проверить поведение на телефоне и отсутствие лишних переходов и кликов в обычной работе. Точный сценарий и визуал определить в отдельной ветке.

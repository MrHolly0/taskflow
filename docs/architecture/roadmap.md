## Как привязать будущие экраны к версии

Для каждого выбранного состояния заполнить в реестре commit, SHA-256 документа, список снимков и краткий сценарий демонстрации. У снимка должны быть раздел, состояние задачи и устройство или размер окна. Отдельно указать, какие данные используются для примера. Настройки записывать без секретов и персональных данных.

После подтверждения дипломного состояния создать отдельный тег `milestone/thesis-reference` на установленном commit. Для окончательного демонстрационного набора аналогично закрепить `milestone/defense-demo`. Сейчас эти теги не создаются: соответствующие версии ещё не выбраны. Зафиксированные теги впоследствии не переносить на новые изменения.

Старый интерфейс при необходимости открывать в отдельной рабочей копии и на отдельном наборе данных. Возврат старого исходного кода не возвращает старую схему базы и состояние аккаунта. Текущий стенд для подбора архивных экранов не переключать.

## Параллельное исследование

JSON продолжает проверяться на новых отложенных репликах и длинных списках. Главные показатели — полностью правильные запросы, точность и полнота действий, суммарные токены с исправлениями, медиана и p95. Последующий опыт должен отделять улучшение метода от настройки на уже знакомом наборе.

Code Mode остаётся исследовательским направлением для составных команд. Его включение в продукт зависит от повторного сравнения качества, задержки, расходов и ограничений песочницы. Это не запланированная обязательная замена JSON. Подготовка статьи идёт параллельно развитию продукта и не заменяет проверку продукта.

## Как показывать результаты на защите

В записке сохраняются утверждения и числа, относящиеся к её срезу. Более поздние эксперименты показываются с собственной датой, версией и методикой. Если на защите открывается новая версия, её следует обозначить как дальнейшее развитие после подготовки соответствующего раздела ВКР.

Для справки: в имеющихся редакциях записки полная корректность августовского прогона составляет 312/448 (69,6 %), после исключения двух деградаций из 450 обращений. В ноябрьском парном сравнении DIRECT получил 351/450 (78,0 %), JSON — 418/450 (92,9 %), и ошибки API остаются в знаменателе. Это разные экспериментальные срезы. Нельзя подписывать их как один непрерывный прогон или приписывать всю разницу только формату JSON. Точность отдельных действий также не равна доле полностью правильных запросов.

Источники новых результатов: [проверка замены планировщика](json-planning-replacement.md) и [проверка защиты ресурсов](model-resource-guards.md). Архивная дорожная карта в `docs/vkr/дорожная-карта.md` сохраняется как исторический материал; текущая последовательность работ ведётся здесь.

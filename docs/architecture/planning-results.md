## Сравнение с текущим режимом

- **JSON-планы**: полностью правильных запросов не меньше — да; точность действий не ниже — да; полнота не ниже — да; медиана и p95 не выше — да. Изменение общего расхода токенов: +29.2% экономии; тарифной оценки: +36.4% экономии.

## Границы измерения

Ожидания исходного датасета не менялись. Использован прежний ActionMatcher; в основной оценке эквивалентные моменты времени приводятся к часовому поясу пользователя. Архивный балл без этой нормализации сохранён в поле legacyCorrect. Неудачные обращения не исключаются из общей доли правильных запросов.

Задержка измеряется для планирования: чтение контекста, обращения к Groq, исправления и выполнение песочницы. Распознавание аудио, внешний туннель и браузер сюда не входят; VOICE_TRANSCRIPT — готовый текст.

Тарифная оценка использует 0.15 USD за миллион входных и 0.60 USD за миллион выходных токенов по [публичному тарифу Groq](https://console.groq.com/docs/model/openai/gpt-oss-120b). Скидки за кеширование и инфраструктура не учтены; это расчёт по usage, а не счёт поставщика. Для отклонённого API ответа usage может быть неизвестен.

Это сравнение полных реализаций: на результаты влияют и формат плана, и инструкции, и объём кандидатов, и интенсивность рассуждений. Экономию нельзя целиком приписывать JSON или Code Mode. Набор использовался при доработке; выводы о новых неизвестных командах потребуют отдельного отложенного набора.

## Дополнительные проверки

Проверки выполнены после основного прогона без изменения кода планировщиков. Это отдельные небольшие наборы; их результаты не добавлены к 450 измерениям основного сравнения.

На напоминаниях медианы составили 893, 539 и 664 мс соответственно. p95 — 3180, 3606 и 1309 мс: у JSON один ответ с исправлением оказался медленнее контроля. На шести инъекциях p95 Code Mode составил 1143 мс против 931 мс DIRECT. Утверждение о меньших задержках относится к основному набору, а не к каждому случаю и каждому малому набору.

В большом контексте было 89 задач, включая нужные задачи за пределами начального окна. Новые режимы правильно выполнили массовый перенос двух просроченных задач выбранной группы. Однако все три режима не завершили скрытую задачу и предложили создание вместо напоминания к существующей скрытой задаче. JSON также создал задачу вместо уточнения неоднозначного переноса. Code Mode верно запросил уточнение. При генерации одного ответа Code Mode потребовалось исправление синтаксиса; его токены и задержка учтены.

SQL-поиск и разрешение результатов покрыты интеграционными тестами. Эти модельные ошибки имеют другую причину: наличие поискового API само по себе не гарантирует, что модель его вызовет. Прямые команды к существующим задачам вне окна требуют дополнительной политики поиска до создания или отказа.

## Вывод для продукта

На исходном наборе оба режима прошли общие критерии: доля полностью правильных запросов, точность и полнота действий выше DIRECT, медиана и p95 ниже, токенов меньше. По совокупности результатов JSON — первый кандидат для дальнейшей доработки: он экономнее и быстрее Code Mode, не требует исполнения программы и в основном прогоне не получил отказов API.

Это не основание сразу менять режим по умолчанию. Есть регрессии в отдельных категориях: неоднозначные реплики — 19/45 у DIRECT, 5/45 у JSON и 9/45 у Code Mode; готовые голосовые расшифровки — 26/30, 23/30 и 21/30. Часть неоднозначных ожиданий требует двух конкретных взаимоисключающих предложений, а не просто уточняющего вопроса; исходная разметка сохранена. Есть и ошибки разбора дат, приоритетов, пропуски действий и недостаточное использование поиска.

Следующий этап — отработать выбор и уточнение, обязательный поиск для обращений к существующим задачам и устойчивость к искажённым расшифровкам. После этого нужны новый отложенный набор, несколько повторов и проверка задержек под параллельной нагрузкой. Прежний набор уже участвовал в настройке инструкций, поэтому его результат нельзя выдавать за независимую оценку обобщения. DIRECT оставлен по умолчанию; переключение продукта и выкладка не выполнялись.

## Проверка реализации

Обычная регрессия: 961 Java-тест без ошибок и пропусков; 5 тестов Node. Образы core-service и nlp-worker успешно собраны. Исполнение программы с поиском проверено из упакованного Docker-образа в отдельном временном контейнере без сети и с файловой системой только для чтения.

На весь цикл пилотов, доработок и финальных проверок использован 2541 HTTP-вызов Groq из согласованного предела 3000. В основном сравнении — 1357 вызовов на 1350 измерений. Использовались только синтетические пользователи и задачи отдельной тестовой базы; реальные задачи не менялись. Промежуточные версии не смешиваются с итоговыми показателями. Работающие сервисы и публичные туннели не перезапускались.

# JSON-планы: проверка полной замены

Ветка `assistant-plan-vs-code-mode` подготовлена к замене DIRECT на BATCH_PLAN. JSON выбран по умолчанию в приложении, обоих Compose-файлах и шаблоне окружения. DIRECT остаётся явным переключателем отката, CODE_MODE — экспериментальным вариантом. Мердж, push и выкладка не выполнялись.

## Критерии

На одинаковом исходном наборе доля полностью правильных запросов, точность и полнота действий должны быть не ниже DIRECT; медиана и p95 планирования — не выше. Экономия токенов учитывается отдельно. Проверка больших списков дополнительно требует правильных целей, сроков и напоминаний, отсутствия лишних изменений и безопасной остановки неоднозначных и слишком больших выборок.

## Парное сравнение: 150 реплик × 3 повтора

Модель `openai/gpt-oss-120b`, Groq. По 450 измерений каждого режима, порядок режимов ротировался; у каждого случая отдельный синтетический аккаунт. Ожидания исходного набора не менялись. Ошибки API входят в знаменатель.

| Показатель | DIRECT | JSON |
| --- | ---: | ---: |
| Полностью правильные запросы | 351/450 (78.0%) | 418/450 (92.9%) |
| Точность типов и целей действий | 95.3% | 99.5% |
| Полнота действий | 83.9% | 92.9% |
| Всех токенов на запрос, с исправлениями | 2684 | 2688 |
| Медиана планирования, мс | 913 | 606 |
| p95 планирования, мс | 2168 | 1366 |
| Запросы с отказом API | 3 | 0 |
| Тарифная оценка USD / 1000 запросов | 0.542 | 0.465 |

Основные критерии выполнены. На коротком исходном наборе суммарные токены практически не уменьшились: экономия выходных компенсирована более подробными инструкциями на входе. Тарифная оценка ниже, поскольку выходные токены дороже входных. Три отказа DIRECT — `HTTP_400:tool_use_failed`; у JSON в этом прогоне отказов API не было.

## Списки по 100 и 200 задач

14 сценариев × 2 размера × 2 режима × 3 повтора = 168 измерений. Цели hidden находятся за исходным окном DIRECT из 80 задач. JSON предварительно подбирает релевантные задачи и показывает модели не более 12 кандидатов; поэтому скрытая для DIRECT задача может попасть в JSON-контекст. Это сравнение полных реализаций, а не одинакового контекста при разном синтаксисе.

| Размер | Полностью верно DIRECT | Полностью верно JSON | Экономия всех токенов JSON |
| --- | ---: | ---: | ---: |
| 100 | 10/42 (23.8%) | 42/42 (100.0%) | 46.5% |
| 200 | 11/42 (26.2%) | 42/42 (100.0%) | 43.3% |

У JSON все 48 проверок дедлайнов и 24 проверки напоминаний совпали до минуты. При обоих размерах медиана и p95 ниже DIRECT. На 200 задачах разница p95 небольшая: 2353 против 2419 мс; её нельзя переносить на любую нагрузку. Снимки задач, напоминаний и расписаний уведомлений основного и чужого аккаунтов совпали до и после планирования.

Строгая оценка запрещает непрошенные поля. У DIRECT некоторые задачи были созданы с правильными сроками, но получили незапрошенную группу — такие запросы не получили полного зачёта. Этот критерий сохранён и не означает ошибку распознавания всех полей.

## Проверка окончательной версии

После дополнительных календарных защит повторён весь исходный набор: JSON — 138/150 (92.0%), точность действий 98.9%, полнота 91.1%, медиана 560 мс, p95 1271 мс. Эти 150 измерений не подмешаны к парному сравнению выше. Качество и задержка остаются в пределах исходного DIRECT-базиса. Это дополнительная проверка, а не новый одновременный парный эксперимент.

Контрольные формулировки: 114/114. Это 19 сценариев на 100 и 200 задачах, по три повтора: необычные отступы напоминаний, ошибки диктовки, смена нескольких приоритетов, перенос с новым напоминанием, отсутствие срока и превышение лимита.

Исходные 14 больших сценариев также перепроверены на окончательной версии: 28/28 на 100/200 задачах, по одному повтору. Они не подмешаны к парным 168 измерениям. [Таблица финальной перепроверки](json-replacement-large-release-results.md).

Архивные явные напоминания — 18/18; инструкции внутри названий задач — 6/6.

Десять дополнительных новых формулировок ранее дали JSON 20/20 на известных фикстурах 100/200 задач. Они не представляют новые предметные области; после использования для доработок контрольные наборы нельзя называть независимыми отложенными выборками.

[Контрольные сценарии](json-replacement-control-results.md), [новые формулировки](json-replacement-wording-results.md), [дополнительные 150 реплик](json-replacement-release-results.md).

## Исправления

- Поиск с учётом форм русских слов, короткие подсказки частичных совпадений и подбор релевантных кандидатов до запроса к модели. Чужие и удалённые задачи исключаются; модель не получает UUID.
- Массовая выборка не обрезается до видимой части. Более 20 целей требуют уточнения; модель не может превратить единичную неоднозначную команду в массовое действие через all:true.
- Смещение напоминания рассчитывается от реального срока задачи или нового срока в этом плане. Переносы и изменения названия применяются перед отдельными напоминаниями, одинаковые активные уведомления не дублируются.
- При единственном временном поле и однозначном относительном дне сервер проверяет отсчёт от текущего дня. Разные даты в одной реплике, неполная или неподдерживаемая формулировка не переписываются глобально. «Послезавтра» не нормализуется в ближайшие завтрашние часы.
- Короткая двоякая ссылка сохраняет выбор существующего или нового дела. Принимается только один вариант, в том числе через обычный endpoint переключения галочки. Быстрое добавление оставляет создание первым.
- Запрет переименования без полного названия оставляет остальные корректные действия с предупреждением. Остальные ошибки формата и небезопасных выборок отклоняют целый план; исправление ограничено одной попыткой.
- Сохранены контракты текстового и голосового ввода, идемпотентные повторные запросы и применение, ручное создание, поведение при недоступности и пустом ответе модели.

## Ограничения и остаточные ошибки

92,9% на исходном парном наборе не означают безошибочную обработку любых команд. Среди оставшихся незачтённых случаев есть разбиение длинной работы на отдельные дела, наследование дней в перечислениях и различение закрытия и отмены. Эти ошибки не удалялись из оценки.

Часть архивных ожиданий противоречива: AM-02 и AM-08 ожидают update без изменяемых полей, AM-09 — перенос без нового срока, AM-13 — завершение вместо напоминания без времени. VT-06 требует сохранить «хлеп», хотя интерфейс рассчитан на исправление ошибок диктовки. Строки и их штрафы оставлены как есть.

Архивный reminders-auto получил 0/18 по старому контракту ответа модели. Он требует автоматических времен уведомления и флага no_reminder_needed, которых нет в действующем контракте JSON; напоминания по настройкам задачи рассчитывает TaskReminderService. Этот архив не используется как критерий смены планировщика. Явные пользовательские напоминания и их реальное сохранение проверены отдельно.

Парные 900 измерений выполнены на срезе fd8f7e9; большие списки — после отдельного защитного исправления календарных часов. Финальные календарные проверки и обработка пустого ответа входят в 2633b2b, переключение по умолчанию — b3d31fb. Контрольные 114 и дополнительные 150 выполнены после этих исправлений. Отпечатки ключевых классов указаны в каждом исходном отчёте. Эти срезы не объединялись в одну выборку.

Измерено планирование готового текста. Распознавание аудио, браузер, Tuna, дополнительный HTTP-переход через рабочий nlp-worker и доставка уведомлений не входят в задержку. Голосовой маршрут локально проверен с подменой расшифровки; это не оценка качества ASR. 100/200 задач одного аккаунта — не нагрузочный тест на 100 одновременных пользователей. Живые API-проверки проведены только на настроенном Groq.

В обоих режимах живой стенд ограничивал ответ 3000 токенами. Температура 0,1; DIRECT сохранял исходные инструкции и reasoning effort поставщика, JSON использовал low и medium при исправлении. Медиана и p95 в таблицах — nearest-rank по строкам измерений. Повторы одних 150 реплик не являются 450 независимыми новыми сценариями.

Тарифная оценка: 0,15 USD за миллион входных и 0,60 USD за миллион выходных токенов по [странице модели Groq](https://console.groq.com/docs/model/openai/gpt-oss-120b), проверенной 08.11.2026. Кэширование, инфраструктура и неизвестный usage отклонённых API-запросов не учтены; это не фактический счёт поставщика.

## Проверки и запуск

Полный `./gradlew test` прошёл с BATCH_PLAN по умолчанию. Интеграционные проверки DIRECT оставлены с явным свойством режима; JsonPlanningApplyIntegrationTest использует настоящий default из application.yml. В локальных JUnit-отчётах 1069 тестов без ошибок и пропусков; неизменённые модули Gradle использовал из актуального кэша. Пройдены 5 Node-тестов песочницы и 4 теста сводки. Проверены записи в реальном PostgreSQL: новый срок и напоминание, отсутствие дублей, выбор одной альтернативы, повторные текстовые и голосовые запросы.

Счётчик этой серии: 2984 HTTP-обращений из 3000, включая пилоты, исправления и остановленные прогоны. Счётчик не сбрасывался; прежние серии хранят отдельные неизменённые журналы.

Все аккаунты и реплики синтетические. Рабочий стенд, чужие контейнеры и туннели не менялись. Для тестов использовались временные PostgreSQL в Testcontainers.

Для включения достаточно стандартной новой сборки core-service и nlp-worker. Liquibase применит миграцию 044 с GIN-индексом поиска; формат задач и HTTP-предложений сохранён. Для отката задаётся ASSISTANT_PLANNING_MODE=DIRECT; удалять индекс или возвращать старую схему не нужно. CODE_MODE не включён по умолчанию.

Локальный архив исходных JSON/JSONL, хешей и журнала квоты: docs/vkr/experiments/2026-11-08-json-replacement/. Он исключён из git. Свёрнутые CSV и таблицы лежат рядом с этим отчётом.
